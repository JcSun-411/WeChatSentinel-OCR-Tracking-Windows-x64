# WeChat Sentinel 验证报告

验证环境为 Windows 11 x64、Python 3.13.1、Node.js 20.19.2。使用合成数据及隔离的临时数据目录。

| 阶段 | 实际验证结果 |
| --- | --- |
| M0 基础工程 | 迁移和健康检查 2 项后端测试通过，前端 1 项单测和生产构建通过。最终 Alembic 为 `0003 (head)`。 |
| M1 Mock 闭环 | 阶段回归 5 项通过。两条示例命中、未命中正文不保存、同一秒不同消息保留、重复投递和重启去重、事务回滚、正则超时及通知回退通过。 |
| M2 历史能力 | 阶段回归 10 项通过，前端构建通过。验证三种格式、预览和映射、非法时间和编码、文件上限、重复导入、公式防护、批次取消及删除。 |
| M3 UIA 适配 | 阶段回归 14 项通过，前端构建通过。本机及便携 EXE 的自检返回 `unavailable`，未发现运行中的微信进程。验证 UIA 依赖可在开发环境导入。 |
| M4 交付 | 最终后端 19 项、前端 1 项通过，类型检查及生产构建通过。`pip check` 无冲突。锁定的前端及 Python 开发/运行依赖扫描均未报告已知漏洞。 |

最终后端额外验证了 1,000 条合成记录的分批入库、分页和删除。在确定第一批 500 条已暂存后请求取消，验证了未完成的数据不可检索，取消后可重新导入。前端测试使用 Vitest。后端的 Starlette 测试客户端发出一条针对 httpx 的兼容性弃用提示。

## 便携包冒烟测试

实际启动构建后的 `WeChatSentinel.exe --no-browser`，使用隔离的 Windows 用户数据目录测试默认 ACL 路径。验证 HTTP 健康检查、首页及 JavaScript 资源、未鉴权数据请求被拒绝、受保护的 SSE、两条 Mock 命中、Windows 通知失败回退、历史 CSV 导入和搜索、JSONL 导出及清理。清理后消息 API 返回空结果。已执行 `WeChatSentinel.exe --diagnose`。

## 悬浮窗增量测试

- 后端 26 项测试通过，包括群标题与成员数同面板约束、会话标识冲突、规则 ID 复用保护，以及仅存目标群关键词命中的合成链路。前端 1 项测试和生产构建通过。
- Windows 原生窗口用合成消息验证了置顶、选群倒计时、授权、命中保存、暂停和窗口关闭后服务退出。
- Windows 便携包启动时已验证带 Tcl/Tk 的悬浮窗入口和回环控制台。等待明确授权期间，数据库里没有自动产生演示消息。
- 用户已打开测试群。当前自动化进程仍未检测到微信，查询前台进程元数据返回访问被拒绝，因此本轮没有完成真实群消息读取。

## 本地 OCR 原型

- 用户的微信 4.2.0.52 真机报告显示，两个 UIA 视图均只看到一个窗口和两个面板，指向文字位置的 MSAA 返回客户区。已记录用户对手选可见区域本地 OCR 的授权。
- 后端 35 项、前端 1 项测试和生产构建通过。覆盖选区越界、禁止复制被遮挡区域、标题不符或读取中变化时丢弃、断档后重建基线、单群限制以及强制只存命中。
- 本地模型读出了合成的中文带人数群名和英文测试气泡。验证时阻断了模型下载请求。另确认 Windows 屏幕复制接口返回指定尺寸的 BGR 区域。
- 原生悬浮窗用合成窗口通过两次框选、授权、全部关键词匹配、命中入库、单群暂停和关闭服务。Windows x64 便携版通过离线自检、未授权窗口受限和回环服务启动检查，授权前消息库为空。
- 未验证用户微信 4.2.0.52 的 OCR 端到端命中率、漏采率和延迟。请用独立窗口、原生主题和一条新测试消息完成首轮验收。

## OCR 连续采集与历史清空

- 旧流程中单气泡冷启动及识别耗时 3.13–3.75 秒。在热模型的七气泡合成帧上，一条变化时识别耗时约 0.68 秒，整帧重新识别约 3.84 秒，未变帧复用约 0.002 秒。数字为单机测试，未计真实桌面截图与入库。
- 后端 44 项与前端测试及构建通过。覆盖 OCR 子进程复用和退出、未变化气泡复用、可区分的重复消息、清空历史后保留规则及采集状态。真实快节奏群聊的漏采率待验证。

## 采集后分类整理（2026-11-25）

- 新增本地解析、分类缓存表及 `0004` 迁移。按编号或重复地点标签拆分，提取地区、科目、薪资范围及计价单位、学生性别、教员要求、时长和安排。面议、多报价、否定性别措辞与异常 OCR 数值保留原文并提示待确认。
- 新页面打开后分批整理旧记录及新增消息，解析在采集锁外。待处理消息使用外键队列和插入触发器，不对全部历史反复反连接计数。接口回归覆盖幂等、分页、筛选、原文关联、删除与清空级联、解析期间原消息被删除、未完成导入排除、旧版迁移保留消息及采集锁内无全表计数。
- 独立审查发现的钟点误作时长、复合时长、频次误作报价、性别上下文串位、无括号地点拆分等问题均补测试并修正。采集暂停时也每 15 秒检查已完成导入。
- 后端完整回归 66 项通过；前端 3 项测试和生产构建通过。首次完整测试与前端构建并行时两个 OCR 冷启动用例超时；单独复测及最后串行完整回归全部通过，未放宽生产或测试超时。
- 内嵌浏览器用 33 条合成消息生成 34 条分类结果，验证分页、地区/薪资/教员性别组合筛选、学生与教员角色分开、原文展开、重置与待确认筛选；已检查浅色与深色页面截图。未连接用户真实数据库或使用真实微信界面完成本轮分类验收。
- 最终便携 EXE 的 OCR 自检、默认 OCR 悬浮窗和显式 UIA 悬浮窗启动通过。用隔离数据库实测分类拆分、金额/地区筛选、角色字段、时长、完整原文读取及重复整理幂等。已核对 EXE 包含最终解析器和有序待处理队列，前端 `has_more` 契约及 `0004` 迁移齐全。

## 同一窗口移动与缩放跟随（2026-11-25）

- 原版选区已随位置平移，但窗口宽高变化直接报错。新版保留标题的左上位置和消息区四边距，用当前窗口矩形及 DPI 换算，并维持同一 HWND/PID、群标题、可见性和遮挡校验。
- 新增回归覆盖扩大/缩小还原、DPI 换算、负屏幕坐标、越界/过小/超大保护、复制中几何变化、缩放后遮挡、worker DPI 传递，以及换行变化复用标识和新增重复气泡仍独立保存。后端完整回归 77 项通过；前端 3 项通过。另覆盖中文标点和 ASCII 冒号处换行去重、保留英文词间空格，以及 125% 显示缩放的合法边界取整。
- `--ocr-tracking-self-test` 在自建 Windows 原生窗口中实际读屏并 OCR，通过 initial、moved、larger、smaller、maximized、restored、too_small_limited、size_recovered、minimized_limited、visible_recovered、covered_limited、uncovered_recovered 共 12 个场景。采集区与独立布局的 Canvas 实际边界逐次一致。诊断保持窗口消息泵响应，并按采集策略重试动画中的短暂受限。
- 诊断仅临时允许读取自建进程的合成窗口，不改变正常采集的微信进程名单，不产生聊天数据库或读取真实聊天。真实微信内部布局和跨 DPI 显示器行为尚未实测；DPI 变化目前由纯映射回归覆盖。输入框/侧栏分隔线另行改变时仍需重选。
- 最终便携 EXE 的普通 OCR 自检与全部 12 个跟随诊断场景通过；默认 OCR 窗口和显式 UIA 窗口均能启动。分类拆分、筛选、原文读取和幂等接口也在便携程序中复验通过。已核对 EXE 包含最终坐标映射、DPI 读取、换行身份复用和诊断入口，分类迁移文件齐全。
