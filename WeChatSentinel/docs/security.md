# 安全与隐私

- 支持的运行方式仅绑定 `127.0.0.1`。服务检查唯一的 Host、Origin 和浏览器 Fetch Metadata。敏感 API 需要应用启动时生成的本地 Cookie 及自定义会话请求头。事件流要求本地会话 Cookie。服务未启用跨站 CORS。
- 浏览器控制台的 UIA 模式读取前台已授权群。悬浮窗只读取解锁桌面上经用户明确点选且可见的微信群窗口。绑定与快照仅保存在进程内。客户端定位使用进程和窗口元数据。源码中的采集路径没有 Hook、进程注入、进程内存读取、提密、数据库扫描、自动发消息或切换群聊。
- 经用户确认启用的 OCR 原型一次只绑定一个微信群。窗口与选区只在本次运行中有效，匹配群标题后才复制手选的可见消息区域，并在识别前后核对标题。帧图像以及没有命中的文字在内存中处理，数据库只落地匹配的文本。模型随便携包提供，识别使用 CPU，运行时不请求外部服务。
- 实时消息默认仅保存命中正文。历史预览需用户主动上传。预览暂存于应用数据目录，提交完成、取消、清理或中断恢复时清除。Windows 默认目录由当前用户与 SYSTEM 的 ACL 保护。SQLite 文件以明文存储。
- 日志与状态仅包含固定错误摘要、类型、请求 ID、计数或技术状态。后端访问日志关闭。前端把正文搜索和规则测试放在 POST 请求体，避免文本进入 URL。Windows 通知仅显示通用提示。
- 清空数据需要显式确认，删除数据库记录、相关索引及应用暂存，并尝试截断 WAL。浏览器下载、备份、操作系统文件缓存和磁盘残留由用户管理。清理不保证数据无法恢复。
- 锁文件固定前后端版本。更新时复查 Windows 采集与通知库的实际调用路径和权限，并分别执行 `pip-audit -r backend/requirements-dev.lock` 与 `npm --prefix frontend audit`。依赖安装与扫描需要网络，应用运行流程无需外部服务。
