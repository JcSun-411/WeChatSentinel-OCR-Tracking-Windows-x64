# 采集文本分类整理实施计划

> 在当前会话按步骤实现，每步先验证测试失败，再实现并验证。

**Goal:** 把已采集文本拆成可检索的结构化条目，保留原文供核对。

**Architecture:** 纯本地规则解析；按明确编号或重复地点标签切割，提取地点、科目、金额范围与单位、学生性别、教员性别要求、时长及上课安排。独立分类表和待处理队列外键关联消息，插入触发器负责新消息入队。页面分批补齐历史及新增记录，解析在采集锁外执行。

**Tech Stack:** 现有 Python/FastAPI/SQLAlchemy/SQLite 与 Vue/TypeScript，不添加模型或网络依赖。

**Spec:** 本轮用户请求与原开发规格书安全边界。

## Global Constraints

- 不改变采集权限、可见区域与关键词规则。原始文本不修改、不上传。
- 不把学生性别当作教员要求；优先、仅限等措辞保留，否定与冲突标记待确认。
- 不混合小时、次、天、月的薪资筛选；不对隐含地址和缺失数值做推断。
- 与原消息删除、清空、导入完成状态保持一致，迁移兼容已有数据库。

## Review Focus

- 同一气泡中多条编号信息、没有换行、没有编号但重复地点标签。
- OCR 中文字间空白、薪资范围与面议、每两小时金额和时长范围。
- 性别优先与排除措辞，学生和教员角色分开。
- 批量整理重入、并发删除、清空关联及未完成导入不可见。
- 原文展示防 HTML 注入，浅深色与窄屏布局可读。
