# WeChat Sentinel
实时监控微信聊条记录 在群聊中找到需要的信息（半成品）

## 添加监控

双击 `Start-Sentinel-Floating.cmd`，或在 VS Code 打开 `backend` 后按 F5。使用便携版时，解压整包并打开 `WeChatSentinel.exe`。

1. 打开目标微信群。在悬浮窗点「添加微信窗口」，倒计时内把鼠标移到群聊窗口内并停住。
2. 核对群名。键入关键词后点「添加」或按 Enter，可以用逗号、顿号一次输入多个。选择「任一关键词命中」或「全部关键词命中」，点「确认并开始」。
3. 重复添加其他群。让各群使用独立聊天窗口并排保持可见，最多同时监控四个窗口。悬浮窗会显示每个窗口是否可采集。
4. 监控中点「添加并保存」可使新关键词生效，移除关键词或切换匹配方式也会自动保存。上方「已保存」显示写入成功的关键词数。关闭悬浮窗会停止采集。下次打开时保留群配置和关键词，需要重新选中微信窗口。

桌面锁定、窗口重叠或最小化会让相应群显示受限。读取依赖该微信版本向 Windows 暴露的控件。更多信息见 [兼容性与验证](docs/uia-compatibility.md)。

## 组合关键词与命中清理

在悬浮窗选择「任一完整关键词组」，输入一组如「报名、周四」并添加，再输入下一组如「组会、地点」。只有同一条消息集齐任意一组的所有词才收录。也可以在网页「匹配规则」里用每行一组的方式设置，并用「测试规则」预览。

在「命中记录」点一行的「删除」并确认，可从本地库移除该条记录及相应命中和通知。群聊内容留在微信。

监控开始后可点「群窗置顶」，帮助已选群窗在普通窗口上方保持可见。旁边的「面板置顶」只控制 Sentinel 悬浮窗。暂停、关闭或改绑时会恢复本程序设置的群窗置顶。OCR 仍需手选区域可见，其他置顶窗口盖住选区、微信最小化或锁屏时会暂停。

## OCR 速度与历史清空

本地 OCR 的关键词匹配会容忍中文相邻字之间由排版产生的空格、换行，记录正文保留原识别格式。本地 OCR 默认每秒尝试截取一次已授权选区，模型常驻并复用未变气泡的识别结果。命中页第一页自动刷新。可以在「诊断与设置」调整 OCR 间隔。选区被遮挡、移出屏幕、最小化或锁屏时仍会暂停，快速连续滚动也可能让消息在两次画面之间滑出选区。

在「命中记录」或「历史记录」点击「清空本地历史」并确认，会清空本机消息、命中、通知日志和导入批次。群配置、关键词规则和采集状态会保留。请先完成或取消正在运行的导入。

## 收集文本的分类整理

在后台左侧点「分类整理」，或在「命中记录」右上角进入。页面打开后，每批整理 50 条已采集消息，随后继续整理新增记录；解析在采集锁外进行。消息详情中的「整理这条消息」只查看该条消息的拆分结果。

- 按明确编号（如 QD20261106）或重复的地点标签拆分多条信息，保留拆分原文和整条消息原文。
- 提取地区、科目、薪资范围与计价单位、学生性别、教员性别要求、每次时长以及上课时间和频次。教员要求的「优先」「仅限」等措辞保留在要求原文中。
- 可以按地区、科目、来源群、两类性别、金额区间、最低时长和原文词语筛选。金额须先选择计价单位，按区间有交集筛选；`130/2h` 按「元 / 2小时」记录，不与小时单价混比。
- 点「核对原文」查看字段及原文。面议、多个报价、否定措辞、地区或薪资缺失和异常数字会标记待确认。当前版本不自动猜测未注明的地区、性别或价格，也不提供人工字段编辑。
- 删除原始命中或清空历史时，相关分类条目一起删除。旧版数据库启动时自动升级，原消息和规则保留；历史导入只整理已完成批次。

分类使用本地规则，不上传消息，也不调用云端模型。它更适合带「地点、薪资、学生情况、教员要求、次数」等标签的文本；自由表达、OCR 错字和缺失上下文仍可能使字段缺失或不准确，需以原文为准。

## Windows 源码安装与运行

在项目根目录打开 PowerShell。需要 Python 3.11 或更新版本与 Node.js 20.19 或更新版本。便携包已包含运行环境，可直接解压启动。

```powershell
Push-Location backend
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.lock -e '.[dev,package]'
Pop-Location
npm.cmd --prefix frontend ci
npm.cmd --prefix frontend run build
.\Start-Sentinel-Floating.cmd
```

完整浏览器控制台可用 `.\scripts\run.ps1` 启动，默认地址为 `http://127.0.0.1:8765`。运行 `.\scripts\diagnose.ps1` 或 `WeChatSentinel.exe --diagnose` 可检查 Windows UI Automation 的可用性，诊断不会输出聊天正文。

## 本地 OCR 原型

微信 4.2.0.52 的真机诊断未读到消息正文控件，可用独立 OCR 原型试读授权群的可见文字。解压 OCR 便携版后，双击其中的 `WeChatSentinel.exe` 或 `Start-Sentinel-OCR.cmd`。OCR 窗口标题带有「本地 OCR」，并提供「选择微信群」按钮。源码环境使用 Python 3.13 x64，先在项目根目录安装可选依赖，再运行 `Start-Sentinel-OCR.cmd`。

```powershell
.\backend\.venv\Scripts\python.exe -m pip install --only-binary=:all: -r backend/requirements-ocr.lock
.\Start-Sentinel-OCR.cmd
```

1. 打开一个有权处理的独立群聊窗口，滚到最新消息，确保能看到至少一个完整的文本气泡。把悬浮窗放在群窗旁边。
2. 点「选择微信群」，把鼠标移到群窗内。先拖框圈住一行群名和括号里的成员数，避开按钮图标，再圈住消息列表，留出气泡边缘并避开输入框、侧栏和聊天背景图。按 Esc 可取消。
3. 核对识别出的群名，添加关键词并选「任一」或「全部」。点「开始采集」，会先筛选当前选区内的可见文字，状态变成「采集中」后继续处理新消息。监控中新增关键词时，点「添加并保存」。下一轮会按新规则重新筛选当前可见文字，后续新消息也按新规则匹配。
4. 「查看记录」打开本地后台。主按钮在「开始采集」和「暂停采集」之间切换。运行中可点「重新选择群」暂停当前绑定并重新框选，用「重扫当前画面」检查当前关键词。重启时保留配置，需要重新授权窗口和选区。

顶部状态显示「采集中」或「等待恢复」，下方提供本轮气泡数和具体受限原因。顶部长气泡因滚动裁切时，利用后续仍可对应的气泡接续采集。短暂遮挡时保留上一轮定位，恢复可见且仍能对应原画面时继续识别新增内容。整屏内容完全替换时也会筛选新识别的文字，并使用内存中最近 256 条气泡标识减少回看重复。重复短文本和快速滚动仍可能造成误判。

模型随 OCR 便携包提供，运行时在本机识别。图片只在内存中短暂处理，数据库只保存匹配的文本。截图、未命中正文、推断出的发送者和原消息时间均不入库。窗口被遮挡、最小化、锁屏、标题不匹配或消息断档时，采集会受限并在恢复后重建基线。普通主题下文字气泡阅读效果较好。长气泡支持读取手选区域内的可见文字，超出选区的内容无法识别，可能导致上下文或组合词不完整。主题变化和快速滚动可能漏采。

## 同一群窗口的移动与缩放跟随

首次选好窗口、标题和消息区并开始采集后，移动窗口、调整普通窗口大小、最大化和还原都无需重新框选。标题保持顶部位置，消息区按原四边距伸缩；显示 DPI 变化时同步换算边距。采集仍绑定原窗口和群标题，不会自动切换到其他群。

拖动或窗口动画期间可能跳过不稳定的一轮；窗口稳定、标题和消息可见后继续。窗口过小、选区超过 400 万像素、最小化、遮挡或锁屏时会等待恢复，无需为恢复原尺寸重新选区。缩放只改变换行时复用消息标识，原始正文保留第一次识别格式。

手动拖动输入框高度、侧栏分隔线或改变主题等操作属于内部布局变化，仍需重新框选。真实微信的不同内部布局和跨显示器缩放需在本机核对，程序不会绕过遮挡读取隐藏窗口。

可执行诊断（只操作自建的合成窗口，不打开数据库或控制微信）：

```powershell
.\WeChatSentinel.exe --ocr-tracking-self-test
# 源码环境，在项目根目录运行：
.\backend\.venv\Scripts\python.exe -m app.launch --ocr-tracking-self-test
```

诊断会测试移动、扩大、缩小、最大化、还原、过小/最小化/遮挡及恢复，并用本地 OCR 读取合成文字。桌面不可访问或读屏失败时会明确报错。

## 测试与打包

```powershell
Push-Location backend
.\.venv\Scripts\python.exe -m pytest -q
Pop-Location
npm.cmd --prefix frontend test
.\scripts\build.ps1 -SkipInstall
```

打包结果位于 `build/portable/WeChatSentinel`。复制或压缩整个目录交付，解压后运行里面的 `WeChatSentinel.exe`。若打包 OCR 原型，构建时加 `-IncludeOcr` 并用独立的 `-OutputDirectory`。可用 `WeChatSentinel.exe --ocr-self-test` 在离线环境诊断模型是否齐全。
